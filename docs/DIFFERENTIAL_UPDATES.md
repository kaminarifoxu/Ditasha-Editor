# Differential downloads — v1.72

The first upgrade from v1.71.1 or earlier is a complete download: those clients do not contain the differential reader. Once v1.72 is installed, compatible later releases can reuse local blocks. Updating a direct installation of v1.72 also works without downloading it a second time.

## How it works

Both published EXEs have an external gzip JSON v2 `.blockmap`, generated by the exact electron-builder version in package-lock. No additional runtime package is needed. Installed clients use the installer copy that NSIS already retains in `%LOCALAPPDATA%/ganomabi-asset-studio-updater/installer.exe`; portable clients use their running portable EXE.

The updater obtains the installed version's public release metadata, verifies the local base's entire SHA-256, and compares its blockmap with the new one. Matching blocks may move to different offsets. They are copied locally; only missing blocks are requested with HTTP Range. The result is a complete EXE and follows the existing installer/restart path. Its size, complete SHA-256 and MZ header must verify before installation becomes available. Originals and presets are not edited during reconstruction.

Transfer progress shows the changed bytes plus both compressed maps, and the reduction relative to the complete package. GitHub API metadata is not included in that estimate. Saved bandwidth varies with actual changes; runtime/creative-engine upgrades can still be large. Reusing blocks needs additional temporary disk space for the completed new EXE and keeps NSIS's existing installer cache.

## Full-download fallback

A missing/different/symlinked base, missing or unsupported blockmap, invalid ranges, reconstruction/hash failure, less than 10% expected savings (including maps), or more than 128 missing ranges triggers a fresh full download. Unsupported future blockmap formats do the same. Maps are bounded to 4 MB compressed, 16 MB decoded and 100,000 chunks. No unverified reconstructed file can be installed. A failed full download continues to show an error.

This does not add pause/resume, apply changes directly to installed files, remove bundled creative engines or promise a fixed download size. SHA-256 verifies release integrity; the existing unsigned Windows executable policy remains unchanged.

## Release and validation

Release builds generate maps for Setup and portable, then test reconstruction over actual HTTP byte ranges through Electron `net.fetch`. Header-mutation fixtures verify correct reconstruction and small transfers on the full built EXEs; those fixture percentages are not representative release benchmarks. CI also generates a map for the previous published installer, verifies its public checksum and measures reconstruction against the new package. The previous release did not need to publish that generated map for this test, but production clients require maps on both releases.

Windows install/reinstall checks verify that NSIS retained the exact current installer. Unit coverage includes moved/duplicate chunks, installed/portable isolation, missing maps, corrupted caches, unsupported/short/corrupt ranges, decompression limits, verification failure and full fallback. New releases remain drafts while all six assets (two EXEs, their SHA-256 files and blockmaps) upload, then become the stable latest release together.

Implementation reference: [electron-builder differential download support](https://www.electron.build/nsis/). The deployed reader deliberately supports the external v2 format emitted by the pinned builder, rather than assuming newer builder formats are compatible.
