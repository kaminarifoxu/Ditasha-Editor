# DITASHA Creative Suite · 1.23 preview

DITASHA hosts the original, unmodified Craft web engines locally inside its desktop window. These are actual Rust/WebAssembly editors, not recreated tool menus or links to hosted websites. The DITASHA shell, homepage, navigation, panels, dialogs and asset surfaces use the new graphite / sage interface; the embedded engines retain their own original editing interfaces and branding.

## Working with textures and models

Use Texture & Model for YTD / DDS, UV overlays, GTA model preview, decals, layers and 3D scene controls. PhotoCraft edits images; it does not replace the GTA resource parser, rigging or 3D renderer.

1. Open your texture in Texture & Model and export PNG.
2. Click Photo Studio beside the 2D / 3D switch. Inside Photo Studio, use File → Open to choose the PNG (or a PSD document).
3. Edit using the engine's layers, masks, retouching and color tools. Save the layered document if you want to continue editing it later; export PNG for GTA.
4. Click **Import edited image** in the DITASHA toolbar. The image opens in Texture & Model. To replace an existing texture while preserving its slot, return to that texture and use **Ganti** to select the PNG, then save YTD.

This is explicit PNG interchange. Edits do not automatically synchronize between engines, and PSD layers are not converted into DITASHA canvas layers. Models still use DITASHA's existing Scene Studio and native build tools.

## Documents and saving

Select a workspace from the home cards or grouped sidebar; Ctrl K searches every workspace. Each engine's File → Open / Save / Export commands manage its documents. The browser build's supported formats apply; this preview does not promise full Photoshop, Illustrator, Premiere or Microsoft Office compatibility.

Switching workspace hides the engine while retaining its document. **Close engine** releases memory and asks you to save first. Closing DITASHA or installing an update also asks you to save creative documents. Browser storage is separated by engine and kept under the app profile; always export important work to ordinary files. An engine's autosave, where supported, is not a substitute for an exported file.

The engines are young upstream projects and retain their existing limitations. No AI account, model service, MCP server, external telemetry or remote editor is started by DITASHA. Engine sessions block external network traffic. Some optional online functions will therefore be unavailable. Downloads generated by engines use DITASHA's native Save dialog.

## Packaging and licenses

`npm run prepare:craft` downloads the nine release ZIPs listed in `config/craft-engines.json`, checks exact byte sizes and SHA-256 digests, validates archive paths, and installs them under ignored `craft-runtime/`. Windows packages include these files via `extraResources`, so end users do not need to install Rust or download engines manually. The source checkout needs preparation before using the engines.

Original source and asset notices are included per engine in `assets/licenses/craft/` and copied into its runtime as `DITASHA-NOTICES.md`. Original bundles and their brands are not modified. The embedded applications are MIT licensed; their fonts and other assets retain separate licenses. DITASHA is independent of the ArtCraft Team.

`smoke-craft.cjs` runs each real engine in an isolated test profile, checks startup, secure context, cross-origin isolation, nonblank rendering, network blocking, workspace retention and explicit engine close. It saves screenshots and a JSON result. Packaging verification compares every prepared engine file against the packaged copy.
